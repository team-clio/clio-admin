# 사이드바 문서 관리 Overview

## 문서 목적

이 문서는 프로젝트 문서 관리 기능의 현재 상태와 개선 범위를 정리한다.
구현 방향과 세부 UI는 다음 단계의 계획 및 결정 기록에서 확정한다.

## 배경

프로젝트 문서는 버그와 이슈를 분석할 때 Agent가 참고하는 프로젝트 맥락이다.
현재 사용자는 프로젝트 설정 화면까지 이동해야 문서 목록을 확인하거나 파일을 업로드할 수 있다.

## 현재 상태

- 사이드바에는 프로젝트 문서 전용 메뉴가 없다.
- 프로젝트 설정 화면 안에서 문서 목록, 업로드, 삭제 기능을 제공한다.
- 업로드는 제목 입력과 브라우저 기본 파일 선택 입력을 사용한다.
- 서버는 프로젝트별 문서 조회, 단일 파일 업로드, 삭제 API를 제공한다.
- 업로드 가능한 형식은 PDF와 Markdown이다.
- 문서별 Agent 동기화 상태를 목록에 표시한다.

## 문제

- 자주 확인하는 문서 목록에 접근하려면 설정 화면을 거쳐야 한다.
- 파일을 탐색기에서 바로 끌어 놓을 수 없어 업로드 흐름이 번거롭다.
- 문서 관리가 프로젝트 기본 정보와 레포지토리 설정 사이에 있어 독립된 작업으로 인식하기 어렵다.
- 현재 레이아웃은 업로드 입력과 목록의 시각적 우선순위가 불분명해 문서를 추가하고 상태를 확인하는 흐름이 끊긴다.

## 개선 방향

- 선택한 프로젝트의 문서 관리 화면을 사이드바에서 직접 연다.
- 업로드, 처리 결과 확인, 기존 문서 탐색이 한 흐름으로 이어지도록 화면 정보 구조와 레이아웃을 재설계한다.
- 문서를 파일 목록 형태로 표시하고 동기화 상태와 주요 메타데이터를 유지한다.
- 드래그 앤 드롭과 파일 선택을 모두 지원하는 업로드 영역을 제공한다.
- 현재 서버 API 계약을 재사용하고, 서버 변경은 필요한 경우에만 별도 범위로 제안한다.

## 작업 범위

### 포함

- 문서 관리 전용 사이드바 진입점과 화면
- 사용 빈도와 작업 흐름을 반영한 문서 관리 화면 레이아웃 재설계
- 프로젝트 미선택, 로딩, 빈 목록, 오류 상태
- PDF 및 Markdown 드래그 앤 드롭 업로드
- 파일 목록과 동기화 상태 표시
- 기존 문서 삭제 기능 유지
- 반응형 화면과 키보드 접근성 검증

### 제외

- 문서 내용 미리보기 및 다운로드
- 서버의 문서 저장·동기화 방식 변경
- 지원 파일 형식 확장
- PCM 지식 문서 화면 변경

## 완료 기준

- 사용자가 사이드바에서 문서 관리 화면을 한 번에 열 수 있다.
- 사용자가 파일을 끌어 놓거나 파일 선택 창을 사용해 업로드할 수 있다.
- 업로드 영역, 상태 안내, 문서 목록의 우선순위가 명확하고 데스크톱과 모바일에서 주요 작업을 쉽게 찾을 수 있다.
- 업로드 결과가 목록에 반영되고 동기화 상태를 확인할 수 있다.
- 기존 문서 삭제 흐름이 동작한다.
- 타입 검사, 린트, 프로덕션 빌드가 통과한다.
- 주요 화면 상태를 Storybook 또는 브라우저에서 확인한다.

## 확인이 필요한 사항

- 사이드바 메뉴 위치와 이름은 계획 단계의 결정 포인트로 확정한다.
- 문서 관리 화면의 정보 구조와 데스크톱 레이아웃은 계획 단계의 결정 포인트로 확정한다.
- 업로드 시 문서 제목을 정하는 방식은 계획 단계의 결정 포인트로 확정한다.
- 여러 파일을 한 번에 드롭할 수 있게 할지는 서버의 단일 파일 API를 고려해 결정한다.
